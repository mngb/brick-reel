# brick-reel

一座被不可破围墙封住的砖块金库，球从缺口钻进去把它啃空。离线逐帧渲染成竖屏 mp4，
专门用来发推特。

不是游戏，是渲染器：模拟以固定步长推进，每帧直接喂给 ffmpeg。输出帧率绝对精确，
渲染快慢完全不影响成片。

## 用法

```bash
npm i

# 1. 先扫种子，挑一条好看的（不渲染，40 个种子约 5 秒）
node src/main.js --scan 60 --min 60 --max 130 --top 8

# 2. 渲染选中的种子
node src/main.js --seed 36 --out out/vault.mp4

# 3. 调画面时用静帧预览，秒出
node src/main.js --seed 36 --preview 40 --out out/f.png

# 4. 想看道具/穿透那一刻长什么样，让它自己找
node src/main.js --seed 36 --find drop
node src/main.js --seed 36 --find pierce
```

### 参数

| 参数 | 说明 |
|---|---|
| `--seed N` | 随机种子。同种子必出同一条视频，逐字节一致 |
| `--cell N` | 每格像素数（默认 30 → 1080×1440）。`--cell 12` 快速试渲 |
| `--cols N` `--rows N` | 网格尺寸，默认 36 × 48 |
| `--palette sunset\|ice\|mono` | 配色 |
| `--scan N [--min S] [--max S] [--top K]` | 模拟种子并按时长筛选，**不渲染** |
| `--preview SEC` | 渲染单帧 PNG |
| `--find drop\|pierce` | 列出值得预览的时间点 |
| `--fps 60` / `--out path` | |
| `--slowmo off` | 关掉最后一球的慢镜头 |
| `--max-duration S` | 时长上限，默认 600（10 分钟） |
| `--crf N` | 码率，默认 21（越小越清晰越大） |
| `--template PATH` | 生成可绘制的网格模板 + 一张示例 |
| `--map PATH` | 用图片当关卡（黑=障碍，其它颜色=砖块） |
| `--text "A/B"` `--density N` | 仅 `level: 'text'` 时有效 |

其余（球速、掉落概率、障碍、版面）在 `src/config.js`。

## 网格

**一切以格子为单位，没有小数。** 画布 = `cols × rows` 个 `cell` 像素的格子，
默认 36 × 48 @ 30px = **1080 × 1440**（3:4 竖屏）。砖块恰好占满一格
（`cell - brickGap` = 26px 见方），围墙、障碍全部落在同一网格上。
`cols`/`rows` 是偶数，所以任何整数 `cell` 都能给出 h264 需要的偶数边长。

纵向预算（48 行）：

```
行  0- 5   上方空间（球绕顶）
行  6-21   金库（26 × 16 格，围墙 1 格，内部 24 × 14 = 336 块砖）
行 22-43   活动区
行 44      挡板
行 45-47   挡板下方
```

## 用图片画关卡

```bash
# 1. 生成模板（同时导出一张当前关卡的示例，方便对照）
node src/main.js --template out/template.png

# 2. 用任意画图软件在 out/template.png 上涂格子

# 3. 用它渲染
node src/main.js --map out/template.png --scan 20 --top 5
node src/main.js --map out/template.png --seed 12 --out out/mine.mp4
```

模板文件是 **720 × 1000**，由两部分组成：

```
上面 36 × 40 格（720 × 800）  ← 你画的地方，每格 20px，每 4 格一条深线方便数
下面 10 行（720 × 200）        ← 印在图里的颜色对照表，读取时整段跳过
```

**对照表就印在模板自己身上**，不用另开文档。它占固定的 10 个格子行，所以整张图仍然是干净的
网格倍数（36 × 50 格），加载器只靠图片尺寸就能算出边界，取上面 40 行、跳过下面 10 行。
你想在对照表里涂什么都不会影响关卡。

场地总共 48 行，可画区只有 40 行——**挡板所在的第 44 行加上方 4 行安全高度不在模板里**，
你画不到那儿，也不必记得避开。`playRows() = paddleRow - safeRows` 和
`templateRows() = playRows + docRows` 是模板、加载器、示例导出三处共用的唯一来源。

| 你涂的颜色 | 含义 |
|---|---|
| 白色 / 透明 | 空 |
| **黑色**（亮度 < 0.22） | 障碍 |
| 任意其它颜色 | 砖块，**用你涂的这个颜色显示** |

方向由**格子左上角的一小块标记**决定，和格子本体的颜色分开：

| 角标 | 含义 |
|---|---|
| 无 | 静止 |
| **纯红 `#FF0000`** | 左右移动 |
| **纯绿 `#00FF00`** | 上下移动 |

这样移动的砖块**不会丢失颜色**——本体是你涂的色，角标只管方向。角标在任何看图软件里
都看得见，所以一眼能分辨哪些格子会动。

匹配半径 50，调色板里离这两个纯色最近的一个有 132 的距离，撞不上。

> **兼容旧图**：把**整格**填成纯红/纯绿仍然有效（这是最初的编码，手绘最省事），
> 只是那样的移动砖没有自己的颜色，会按行取调色板色。整格纯蓝/纯品红同样仍表示移动障碍。

### 分组与碰撞

相邻（四邻接）且**同轴**的移动格子构成一组，整体同步移动。障碍和砖块只要同轴就能同组
（"移动的障碍物或砖块是相邻的，则它们构成组"），但左右组和上下组永远不会合并。

碰到**其它砖块、障碍物或边界**时整组反向。实现上，组以「整格」为单位推进：只有在完全
对齐网格的那一刻才做占位检测，中途不可能有东西挡路——所以「碰到就反向」是精确的，
一组永远不会和它撞上的东西重叠。上下移动的组被限制在模板的 40 行内，不会滑进挡板区。

打碎移动砖块会即时重算连通分量：一条 7 格的移动砖被从中间打断，会真的**裂成两组**
各自独立运动，而不是继续锁在一起。

几点实现上的保证：

- **网格线不会被当成内容。** 采样取每格内部 3×3 共 9 个点投票，淡灰线和抗锯齿边缘都影响不了结果。
- **任意图片尺寸都能用。** 图片会按自身宽高均分成 `cols × rows` 格来采样，所以你放大模板画、或者直接丢一张 36×48 的像素图，结果一样。
- **往返无损。** `--template` 导出的示例图读回去能复现出完全相同的关卡（实测 0 个格子有差异，砖块颜色逐个一致）。
- **缺口会自动识别。** 挡板瞄准需要知道墙上的开口在哪；对自绘关卡，程序会找出「贴着墙、且三格内直线能看到砖」的空格子作为门口，所以智能瞄准对你画的关卡同样生效。
- 障碍统一用 `wallColor`（钢灰）渲染，不是黑色——黑色在深色背景上看不见。黑色只是模板里的**标记**。
- **尺寸不对会被指出来。** 喂一张比例不符的图，加载时会打印提示并给出正确尺寸，
  而不是默默把关卡压扁。
- **`out/map-demo.png` 是一张现成的示例地图**，六种类型都用上了，可以直接
  `--map out/map-demo.png` 跑，也可以拿它当起点改。

## 场上有什么

**金库（`level: 'chamber'`，默认；`--map` 会切到 `'image'`）。** 一圈不可破的围墙包住一整块砖。围墙按种子被
打出若干缺口：每边随机 2-3 个（每个 `gapSize` 3 格），**底边额外保证一个 5 格宽的入口**。
底边正对挡板，如果只留窄缝，球会陷入始终撞不中缺口的往复循环，整局零进展。

**会瞄准的挡板。** 出球角度只由球撞在挡板上的位置决定，所以挡板可以真的瞄。
优先级：射线无遮挡能打到的砖 → 通往内部的缺口 → 都不行才退回摆动。
对墙体做 DDA 射线检测，缓存 6 帧一次。这条改动把清场率从 20/30 拉到 **29/30**，
时长从 70-290s 收敛到 40-175s。

**道具掉落。** 每打碎一块砖有 `drops.chance`（4%）概率掉一个，同屏最多 `maxActive` 个。
挡板会主动去接，但只在没有球更紧急时绕路，接道具永远不会导致漏球。

| 道具 | 颜色 | 效果 |
|---|---|---|
| 分裂 | 青绿 | 场上每颗球一分为二 |
| 三分裂 | 冰蓝 | 场上每颗球一分为三 |
| 不反弹 | 粉 | 球撞到砖直接穿过去，不反弹 |
| 挡板变长 | 琥珀 | 每吃一个再 ×`paddle.wideStep`（1.5），可叠加至 `wideMax`（4.5×），到期一次性归位 |
| 冻结 | 紫 | 所有会动的砖块和障碍原地停住 |
| 边界穿越 | 绿 | 球从一侧边界出去，从对侧原方向进来，上下左右都适用 |

前三种是瞬时的（分裂立刻发生），后四种按 `drops.duration` 计时。
画面上不显示倒计时，靠效果本身的视觉线索判断：穿透时球带粉环、冻结时会动的格子蒙冷色、
穿越时场地四边发绿光、变长时挡板肉眼可见地更宽。球数上限仍是 `ball.maxCount`。

**边界穿越期间球不会丢失**——从底边出去会从顶边回来。这是它最强的地方，也是刻意的：
效果结束后规则立刻恢复。

穿透期间球带粉色光环和粉色拖尾；冻结期间会动的格子蒙一层冷色；穿越期间场地四边发绿光。

> 三点说明：
> 1. "分裂"实现为**球**分裂成两颗（不是砖块裂成两块）。
> 2. 穿透只对可破砖生效，**围墙照样把球弹开**——否则金库就没意义了。
> 3. `level: 'text'` 仍然保留，用位图字体把文字铺成砖块马赛克。

## 网页编辑器

`index.html`（本地直接用浏览器打开，或经 GitHub Pages 访问）；另有 Artifact 版
<https://claude.ai/code/artifact/cdc3e06e-13e1-4d29-be6d-c8c98312c2a1>。

- 左栏 7 种格子类型，每行带色块和色值；静止砖块有 14 个安全色 + 取色器
- **形状工具**：铅笔、直线、曲线（拖出弦 → 移动鼠标弯曲 → 点击落笔）、矩形、椭圆，
  矩形和椭圆可切换描边/填充；**水平翻转**把形状替换成它的镜像（不是叠加），包围盒不动
- **Select**（和铅笔同级的一个形状）：拖出选框把里面的内容整体抬起，再拖到别处放下。
  方向键逐格微调，`Delete` 清空，`Esc`/`Enter` 落下。拖出网格的部分只是不显示，
  内容不丢，拖回来就还在
- **复制 / 剪切 / 粘贴**：`Ctrl C` `Ctrl X` `Ctrl V`。粘贴出来的是一份新的浮动选区，
  落在光标位置，可以先微调再放下。类型和颜色都会带过去
- **缩放选区**：`+` / `-` 按 0.25 步进，`0` 复位。重采样的是最初抬起的原始块而不是当前显示的
  格子，所以缩小再放大是**无损**的（3×3 缩到 2×2 再回 3×3，形状精确还原）。
  格子网格上用最近邻，只会复制或丢弃格子，不会出现混色
- 导入现有 PNG 继续编辑；实时显示模拟器会看到的砖块数、墙数、移动组数
- 导出即 720×1000 完整模板，可直接 `--map`

## 结构

```
src/sim.js        物理、道具、规则。无 canvas、无时间源、无 Math.random
src/render.js     只读 state 画一帧
src/fx.js         拖尾、碎块、抖动、闪白（种子化，同样确定）
src/encode.js     raw RGBA -> ffmpeg -> h264/yuv420p
src/level.js      文字 -> 砖块矩阵
src/obstacles.js  不可消除障碍的图案库
src/font.js       5x7 位图字体，砖块和 HUD 共用
```

三个关键设计：

**模拟和渲染分离。** 所以能在几秒内扫完几百个种子挑最好看的一局，而不是渲染完才发现
节奏不对。挑种子是这个项目里最值钱的杠杆。

**`runFrames()` 是唯一的推进入口。** `--scan`、`--find`、真正渲染走同一个循环，
所以扫描报的秒数就是成片秒数（已验证：150.23s → 150.233008s）。

**慢镜头是免费的。** 最后一块砖将被击中时，模拟步长除以 4 但照常每帧输出，即 4 倍慢放。
触发条件是"某颗球已逼近到 430px 内"，所以是一个短促的高潮，不是漫长的游荡。

## 三个刻意的取舍

- **漏掉的球会消失。** 挡板没接住的球直接没了，最后一颗球丢掉这一局就结束。
  `floorBounce: true` 可以改回"底边是墙、永不失球"的老行为。
- **地板反弹带角度扰动。** `floorScatter`（0.5 弧度），仅在 `floorBounce` 打开时有用。
  完全弹性的地板会让球锁进某个再也碰不到挡板的循环，整局零进展。
- **挡板照常绕路接道具，即使只剩一颗球。** 试过"只剩一球就不冒险"，实测反而更差：
  不接道具就分裂不出新球，更长时间困在单球状态，全丢的局数从 3 升到 4。
- **挡板是预言机。** 解析预测落点（折叠墙面反射），`paddle.sloppiness` 调惊险程度。
- **撞击震动默认关闭。** `shake: 0`。设成 `1` 恢复原来的镜头抖动，中间值可以调轻重。

## 时长上限

`maxDuration: 600`（10 分钟）。超过这个长度的局在 `--scan` 里算作没清完。

两点实际影响：

- **渲染成本随时长线性增长。** 一条 10 分钟的片子是 36000 帧，1080×1440 下大约要渲 14 分钟，
  crf 21 出来约 110MB。
- **推特标准账号的视频上限是 2 分 20 秒**，10 分钟的片子需要会员账号才能发。

## 出片规格

1080×1440 / 60fps / H.264 high / yuv420p / faststart。
`yuv420p` 是必须的，否则部分客户端播出来是黑屏。
想要别的尺寸就调 `--cell` / `--cols` / `--rows`，画布永远等于网格。
